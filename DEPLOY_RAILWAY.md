# ServiGo — Railway Deployment

## Local development

The project continues to use SQLite when `DATABASE_URL` is empty:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
Copy-Item .env.example .env
python manage.py migrate
python manage.py seed_demo
python manage.py runserver
```

## Railway deployment

1. Push this repository to GitHub (do not commit `.env`, `venv`, or `db.sqlite3`).
2. Create a Railway project and deploy the GitHub repository.
3. Add a **PostgreSQL** service to the same Railway project.
4. Add/reference the PostgreSQL service's `DATABASE_URL` on the Django service. Railway provides `DATABASE_URL` from its PostgreSQL service.
5. Add these variables to the Django service:
   - `SECRET_KEY` = a new long random production secret
   - `DEBUG` = `False`
   - `ALLOWED_HOSTS` = your Railway hostname (or set `RAILWAY_PUBLIC_DOMAIN`)
   - `RAILWAY_PUBLIC_DOMAIN` = the hostname generated by Railway, e.g. `servigo-production.up.railway.app`
   - `EMAIL_BACKEND` = `django.core.mail.backends.console.EmailBackend` for demo deployments, or configure SMTP variables for real email
6. Railway can use the included `Procfile`. It runs migrations before Gunicorn starts.
7. Generate a public domain from Railway Networking.

### Recommended Railway start command

```bash
python manage.py migrate && gunicorn config.wsgi:application --bind 0.0.0.0:$PORT --workers 2 --access-logfile - --error-logfile -
```

### First production admin

After the service is deployed, open Railway's service shell and run:

```bash
python manage.py createsuperuser
```

Do not run `seed_demo` on every deployment. Use it only if you intentionally want demo records.

### Notes

- SQLite remains available for local development.
- PostgreSQL is used automatically when `DATABASE_URL` is present.
- Static files are served with WhiteNoise.
- User-uploaded media is still stored on the application filesystem. For a production system with persistent uploads, use object storage or a persistent volume.

## Build and start commands

- Build: `./build.sh`
- Start: `./railway-start.sh`

The application automatically uses SQLite locally and PostgreSQL when Railway provides `DATABASE_URL`.
